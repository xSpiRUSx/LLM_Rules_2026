# LLM Rules

Единый набор моих правил для LLM-агентов. Правила пишутся здесь и одинаково распространяются на все проекты.

## Структура

| Путь | Назначение |
|---|---|
| `rules/` | То, что распространяется в проекты |
| `rules/AGENTS.md` | Главный файл правил для агентов, одинаковый во всех проектах; короткий, ссылается на остальное |
| `rules/instructions/` | Инструкции по темам — «как делать» |
| `rules/docs/` | Справочные материалы — «как устроено», агент читает по необходимости |
| `skills.json` | Источники скиллов и ветки, из которых устанавливаются обновления |
| `scripts/Install-Rules.ps1` | Установка и обновление правил и скиллов в проекте |
| `scripts/Install-Skills.ps1` | Установка и обновление скиллов из списка источников |
| `THIRD_PARTY.md` | Происхождение скиллов и сведения об их лицензиях |
| `AGENTS.md` | Правила для агента, работающего в этом репозитории; в проекты не распространяется |
| `CLAUDE.md` | Подключает `AGENTS.md` для Claude Code |
| `VERSION` | Текущая версия набора правил |
| `CHANGELOG.md` | История изменений по версиям |

## Версионирование

Используется [SemVer](https://semver.org/lang/ru/): `MAJOR.MINOR.PATCH`. Версия одна на весь набор правил.

| Часть | Когда повышается |
|---|---|
| `MAJOR` | Изменение, после которого проекту нужно что-то переделать: правило удалено или переименовано, смысл правила изменён на несовместимый, изменена структура репозитория |
| `MINOR` | Добавлено новое правило или существующее расширено без противоречия прежнему поведению |
| `PATCH` | Уточнена формулировка, исправлена опечатка, смысл не изменился |

До версии `1.0.0` набор считается нестабильным: несовместимые изменения допускаются в `MINOR`.

## Как выпускается обновление

1. Изменить файлы в `rules/`.
2. Добавить запись в `CHANGELOG.md` в раздел `Unreleased`.
3. При выпуске: перенести `Unreleased` под новый номер версии с датой, обновить `VERSION`.
4. Закоммитить и поставить тег `vX.Y.Z` на этот коммит.

Источник истины о версии — тег в git. `VERSION` дублирует его, чтобы версию было видно в копии правил без git.

## Подготовка компьютера

Правила требуют MCP-сервер [rlm-tools-bsl](https://github.com/Dach-Coin/rlm-tools-bsl) для анализа кода 1С.
Он ставится один раз на компьютер, а не в проект.

1. Установите службу по [инструкции автора](https://github.com/Dach-Coin/rlm-tools-bsl#установка) (PowerShell от имени администратора).
2. Зарегистрируйте сервер в агенте для своего пользователя:

   ```powershell
   claude mcp add --scope user --transport http rlm-tools-bsl http://127.0.0.1:9000/mcp
   ```

   Для других агентов сервер прописывается в их настройках пользователя тем же адресом.

## Установка правил в проект

Для установки нужны PowerShell 7+, Git и доступ к источникам скиллов.
Обновите локальный клон этого репозитория (`git pull --tags`) и выполните из его корня:

```powershell
./scripts/Install-Rules.ps1 -Project 'C:/Projects/MyProject'
```

По умолчанию ставится последний тег `vX.Y.Z`; другую версию задаёт `-Version`.
Для обновления выполните ту же команду. Правила, список скиллов и установщик
скиллов берутся из выбранной версии.

Что получает проект:

| Путь в проекте | Откуда | При обновлении |
|---|---|---|
| `AGENTS.md` | `rules/AGENTS.md` | Перезаписывается |
| `.agents/instructions/`, `.agents/docs/` | `rules/instructions/`, `rules/docs/` | Заменяются целиком |
| `.agents/project-context.md` | `rules/project-context.md` | Создаётся один раз, дальше не трогается |
| `.agents/VERSION` | Версия, указанная при установке | Перезаписывается |
| `.agents/skills/` | Источники из `skills.json` | См. ниже |
| `.claude/skills` | Ссылка (junction) на `.agents/skills` для Claude Code | Пересоздаётся |
| `CLAUDE.md` | Строка `@AGENTS.md` | Создаётся, если его нет |
| `.gitignore` | Строки `.v8-project.json` и `/.claude/skills` | Дописываются, если их нет |

Всё, что относится к конкретному проекту, хранится только в `.agents/project-context.md`.
Если в проекте уже есть свой `AGENTS.md`, первая установка останавливается:
перенесите его содержимое в `project-context.md` и удалите файл.
Ссылка `.claude/skills` не коммитится и создаётся установщиком на каждом компьютере.

## Скиллы

Копии скиллов в репозитории не хранятся. Источники перечислены в `skills.json`.
Скиллы ставятся в `.agents/skills/` — общую папку стандарта Agent Skills.
Скиллы 1С берутся из ветки `port-agents`, собранной автором под эту папку.
Claude Code читает только `.claude/skills`, поэтому для него создаётся ссылка.

`Install-Rules.ps1` вызывает `scripts/Install-Skills.ps1` сам; отдельно его можно
запустить с параметром `-Destination`. Скрипт загружает актуальное состояние
ветки `port-agents` для `cc-1c-skills` и копирует `grillme` из `.agents/skills/grillme`
в домашней папке пользователя. На другом компьютере этот локальный источник
нужно предварительно установить либо заменить в списке источников.

Скрипт сначала получает и проверяет все скиллы, включая вспомогательные файлы,
затем целиком заменяет одноимённые папки в назначении. Локальные изменения
в этих папках перезаписываются; другие папки сохраняются. Если скилл удалён
из источника, его прежняя установка автоматически не удаляется.
При ошибке получения источника назначение остаётся без изменений.
В конце выводятся количество установленных скиллов и коммиты Git-источников.
Пользовательские настройки Git для подключения к сети применяются как обычно.

Обновления скиллов следуют их источникам независимо от версии набора правил.
Для фиксации версии Git-источника можно указать тег в поле `ref`.

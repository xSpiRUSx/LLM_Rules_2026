# Интерфейс управляемых форм

## Область применения

- Новую форму проектируй целиком по этому стандарту, используя подходящий образец проекта.
- В существующей форме применяй правила к добавляемым и изменяемым элементам. Сохраняй привычное расположение остальных элементов, стандартные команды и пользовательские настройки.
- Перестройка всей существующей формы требует отдельной задачи. Не переносить старые кнопки и поля только ради единообразия с новой формой.
- Способ изменения типовой формы выбирай по политике проекта. Правила оформления сами по себе не разрешают прямое изменение типовой конфигурации.
- Перед реализацией проверь поддержку выбранных элементов версией платформы, режимом совместимости, целевым клиентом и доступным инструментом редактирования. Не придумывай свойства или конструкции из примеров других инструментов.

## Выбор компоновки

До изменения определи основной сценарий, главное действие, необходимые параметры и способ показа результата. Если задача уже задает расположение элементов, используй его; иначе выбери подходящую компоновку:

| Вид формы | Компоновка по умолчанию |
| --- | --- |
| Документ | Основные реквизиты в шапке; табличные части в рабочей области; итоги рядом с таблицей; комментарий и ответственный внизу. |
| Обработка | Параметры операции, затем рабочая область с данными, затем результат. Команды всей формы в верхней панели, команды таблицы рядом с таблицей. |
| Список | Отборы над списком; список занимает основную область; команды выбранных строк находятся в панели списка. |
| Элемент справочника | Наименование и основные реквизиты первыми; дополнительные сведения отдельным блоком. Простую форму не усложнять вкладками. |
| Диалог или мастер | Вопрос или описание шага, параметры, результат; единая группа действий внизу, основное действие справа. У мастера — «Назад», «Далее» или конкретная завершающая команда, «Закрыть». |

Это варианты компоновки, а не требование создавать все перечисленные блоки. Вкладки нужны для самостоятельных разделов или нескольких больших таблиц; одну небольшую таблицу не скрывай на отдельной вкладке без необходимости.

## Команды и кнопки

### Размещение

- Все новые кнопки действий обычной рабочей формы размещай в командных панелях. Команды всей формы — в панели формы, команды таблицы или выбранных строк — в панели соответствующей таблицы.
- В полноэкранной форме основное действие располагай слева в верхней командной панели. Связанные вторичные действия объединяй по смыслу: загрузка, проверка, выгрузка, печать.
- Не разбрасывай отдельные кнопки между полями ввода. Встроенные кнопки выбора, открытия и очистки поля остаются у поля; для перехода к подчиненной форме используй гиперссылку, если это соответствует интерфейсу проекта.
- Исключение для диалогов и мастеров — единая нижняя группа действий. Не дублируй эти же действия в верхней панели. Не отключай стандартную панель у обычной рабочей формы ради собственного ряда кнопок.
- У новой панели проверь источник команд и область действия. Автозаполнение и ручное добавление не должны создавать дубли кнопок, в том числе при смене страниц.
- Для команды строки обозначай область действия заголовком или контекстом панели: «Удалить выбранные строки» должно быть отличимо от «Очистить таблицу».

### Основное действие и визуальный акцент

- Выделяй основное действие сценария штатным акцентом интерфейса проекта. Вторичные команды оставляй без такого акцента.
- На текущем шаге задавай одно безопасное действие по умолчанию. При переключении шага мастера обновляй его; одновременно назначать несколько действий по умолчанию нельзя.
- Визуальное выделение и действие по умолчанию — разные настройки. Если выделяешь еще одну равнозначную команду, не назначай ей второе действие по умолчанию.
- Не делай удаление, массовую перезапись или другую опасную операцию действием по умолчанию. Если безопасного основного действия нет, оставь форму без действия по умолчанию и объясни выбор.
- Цвет и шрифт выбирай из принятого оформления проекта. Произвольные яркие цвета и выделение всех кнопок одновременно не применять. Цвет дополняет понятный заголовок и не является единственным обозначением смысла.

### Названия и состояния

- Заголовок команды должен называть действие: «Загрузить товары», «Проверить данные», «Сформировать документы». Не используй неопределенное «ОК», если можно назвать результат.
- Доступность команды согласуй с текущими параметрами, выбранными строками и состоянием операции. Причину недоступности поясняй рядом с параметрами или в подсказке.
- На время длительной операции предотвращай повторный запуск и показывай состояние выполнения. После завершения или ошибки восстанавливай доступность корректно.
- В подтверждении опасной операции укажи действие и затрагиваемые данные; положительная кнопка повторяет действие. Закрытие диалога крестиком означает отмену.

## Группы и порядок элементов

- Объединяй связанные поля по смыслу и последовательности работы. Примеры заголовков: «Параметры загрузки», «Отбор», «Результат».
- Заголовок группы показывай, если он помогает понять содержимое; не добавляй в пользовательский заголовок слово «Группа». Не создавай декоративные группы для каждого отдельного поля.
- Важные и часто используемые элементы размещай сверху и слева. Реквизит, меняющий доступность или состав формы, должен стоять перед зависимыми элементами.
- В сложной шапке допустимы две колонки: основные реквизиты слева, организационные и дополнительные справа. Не добивайся симметрии пустыми элементами или избыточными отступами.
- Обязательные и часто используемые поля оставляй видимыми. В сворачиваемые или всплывающие группы помещай только дополнительные, редко используемые сведения; заголовок должен объяснять, что внутри.
- Скрытие редко меняемого поля допустимо только при понятном сценарии: значение автоматически заполняется или сохраняется, а пользователю доступен способ проверить его при необходимости.
- Выравнивай поля и заголовки средствами группировки и выравнивания. Не используй пробелы и декорации-надписи для имитации сетки.

## Поля, подсказки и переходы

- Ширину поля выбирай под ожидаемые значения, длинный текст показывай многострочно с заголовком сверху. Не задавай одну фиксированную ширину для всех реквизитов независимо от содержания.
- Для поля с выбором значения обеспечь понятный способ выбора. Очистку допускай, если пустое значение допустимо и имеет определенный смысл.
- Скрывать заголовок можно только у очевидного поля. Подсказка ввода должна пояснять значение, включая смысл пустого значения, например «По всем организациям».
- Флажок формулируй положительно: «Проводить документ при записи». Избегай отрицаний, которые пользователь должен мысленно отрицать еще раз при снятии флажка.
- Для небольшого числа взаимоисключающих вариантов используй поддерживаемый переключатель или список. Двоичный элемент не должен изображать выбор нескольких разных значений.
- Подсказка объясняет неочевидное правило, формат или последствие действия. Не повторяй в ней заголовок и не показывай навязчивые пояснения при каждом открытии формы.
- Гиперссылка служит переходом к связанным сведениям. Название должно объяснять назначение: «Параметры загрузки», а не «здесь» или «подробнее». Не маскируй операцию записи данных под переход.
- Используй стандартные или принятые в конфигурации картинки. Не вводи отдельный набор изображений без потребности задачи.

## Таблицы, отборы и итоги

- Таблица должна занимать основную рабочую область и расширяться вместе с окном. Не ограничивай ее маленькой фиксированной высотой при свободном месте.
- Располагай колонки по сценарию пользователя; данные только для просмотра и расчетные итоги делай недоступными для редактирования.
- Заголовки колонок должны быть краткими и понятными. Выравнивание заголовка согласуй с данными; числовые значения и итоги выравнивай последовательно.
- Отборы размещай отдельной зоной над списком. Если включение отбора задается отдельно от значения, держи флажок использования рядом с полем; снятие флажка отключает отбор без потери введенного значения.
- Итоги размещай рядом с соответствующей таблицей или под ней. Указывай единицы измерения и валюту там, где без них значение неоднозначно.
- Для одинаковых условий используй одинаковое условное оформление. Ограничивай число цветов; ошибки и предупреждения поясняй текстом. Не используй условное оформление как замену отбору строк.

## Результат и сообщения

- Пользователь должен различать состояния «данные не загружены», «нет подходящих строк», «операция выполняется», «операция завершена» и «ошибка» там, где они есть в сценарии.
- Предупреждение показывай отдельным понятным блоком только при соответствующем состоянии. После устранения причины убирай устаревшее предупреждение.
- После выполнения обработки показывай результат: что сделано, сколько объектов обработано, какие строки пропущены и что требует исправления. При частичном успехе не сообщай, что вся операция выполнена успешно.
- Ошибку заполнения связывай с соответствующим полем. Пользовательское сообщение объясняет причину и следующий шаг; технические подробности размещай согласно правилам проекта.

## Имена новых элементов

Сохраняй соглашения проекта и префикс добавляемых элементов типовых форм. Для новой самостоятельной формы допустимы имена, показывающие назначение:

| Назначение | Пример имени |
| --- | --- |
| Параметры операции | `ГруппаПараметрыЗагрузки` |
| Панель формы | `КоманднаяПанельФормы` |
| Панель таблицы | `ДанныеКоманднаяПанель` |
| Колонка таблицы | `ДанныеКоличество` |
| Команда и кнопка | `ЗагрузитьТовары`, `ЗагрузитьТоварыКнопка` |
| Отбор и признак использования | `ОтборОрганизация`, `ОтборОрганизацияИспользование` |
| Предупреждение | `ГруппаПредупреждение`, `ПредупреждениеНадпись` |

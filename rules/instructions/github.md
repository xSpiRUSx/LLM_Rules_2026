# GitHub: задачи, ветки, PR

Задачи ведутся в GitHub Issues, ревью — в Pull Request. Работа с GitHub — через `gh` CLI.

## Issue

- Оформляй по шаблону из `.github/ISSUE_TEMPLATE/`: `feature.md` — доработка, `bug.md` — ошибка, `epic.md` — большая задача.
- Одна issue — один результат. Попутные находки оформляй отдельными issue.
- Issue пишется до работы и не содержит реализации; реализация и проверки — в описании PR.
- Метки из шаблона нет в репозитории — создай её через `gh label create`.
- Задача не влезает в один PR — заводи эпик и подзадачи через Sub-issues. PR делается только на подзадачи; эпик закрывается, когда закрыты все подзадачи и пройдена итоговая проверка.

## Ветки и коммиты

- Одна issue — одна ветка от `main`: `feature/<N>-<кратко>` или `fix/<N>-<кратко>`, где `N` — номер issue.
- В `main` напрямую не коммить.
- Сообщение коммита начинай с типа: `feat:`, `fix:`, `chore:`, `docs:`.

## Pull Request

- Оформляй по `.github/pull_request_template.md`, первая строка — `Closes #N`.
- Галку в «Проверено» ставь только после фактического запуска. Что не запускалось — в «Не проверено».
- Issue закрывается мержем PR, а не вручную.

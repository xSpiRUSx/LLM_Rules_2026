# Расширения конфигурации

## Граница расширения

- Не заимствуй объект и не перехватывай метод, пока не подтверждено, что задача не решается собственным объектом расширения, подпиской или публичным API основной конфигурации.
- Заимствуй минимально необходимый состав. Чем шире заимствованный объект, тем выше риск конфликта при обновлении конфигурации поставщика.
- Новые объекты и реквизиты называй по проектному префиксу. Процедуры перехватчиков дополнительно должны иметь устойчивый префикс расширения, чтобы не конфликтовать с другими расширениями.
- Не создавай скрытую обязательную зависимость одного расширения от другого

## Выбор перехватчика

- `&Перед` и `&После` используй для ограниченного дополнения поведения, когда исходный метод должен продолжить работу.
- `&Вместо` применяй только когда контролируешь полный сценарий замещения. Явно реши, должен ли и когда выполняться `ПродолжитьВызов()`.
- `&ИзменениеИКонтроль` используй для минимальной контролируемой правки тела поставляемого метода. Сохраняй маркеры изменения и не переписывай незатронутые блоки.
- Не имитируй один вид перехватчика другим ради удобства: выбор определяет совместимость с будущими версиями основной конфигурации.

# Контекст проекта

Этот файл создан из шаблона правил и должен описывать только фактический контекст текущего проекта.

При первоначальной установке AI-агент обязан интерактивно собрать недостающие сведения и сам заменить все плейсхолдеры фактическими значениями. Пользователь не должен редактировать этот файл вручную. Заполненный `project-context.md` считается авторитетным источником смыслового контекста для AI-агента.

Если обязательное значение неизвестно, установщик должен продолжить интерактивный опрос и не завершать частично заполненную установку.

## Статус заполнения

При установке агент должен заполнить и отметить выполненные пункты:

- [ ] Тип проекта указан.
- [ ] Название конфигурации указано.
- [ ] Версия платформы указана.
- [ ] Режим совместимости указан.
- [ ] Наличие и версия БСП указаны.
- [ ] Структура исходников проверена.
- [ ] Политика доработок указана.
- [ ] Политика расширений указана.
- [ ] Команды проверки проверены фактическим запуском или помечены как отсутствующие.

## Общая информация

- Тип проекта: 1С-конфигурация / расширение / внешняя обработка / внешний отчет.
- Название конфигурации: `<заполнить>`.
- Версия платформы: `<заполнить>`.
- Режим совместимости: `<заполнить>`.
- Используется БСП: да / нет / неизвестно.
- Версия БСП: `<заполнить>`.
- Основной режим работы: управляемое приложение / обычное приложение / смешанный.
- Основная база разработки: файловая / серверная / не указано.

## Окончания строк

- Окончания строк зафиксированы в `.gitattributes`: да / нет.
- Политика: CRLF для исходников 1С / LF везде / `<заполнить>`.
- История нормализована через `git add --renormalize .`: да / нет / не требовалось.


## Политика доработок

- Типовая конфигурация изменяется напрямую: да / нет / только по согласованию.
- Расширения разрешены: да / нет / предпочтительно / только по согласованию.
- Подписки на события предпочтительны: да / нет / зависит от задачи.
- Визуальные изменения типовых форм: разрешены / запрещены / только программно / только по согласованию.
- Новые объекты создаются в: основной конфигурации / расширении / уточнять по задаче.
- Новые реквизиты добавляются в: основную конфигурацию / расширение / уточнять по задаче.
- Новые роли создаются: да / нет / только по согласованию.
- Изменение существующих ролей, прав и RLS: запрещено без отдельного согласования.

Если политика не заполнена, агент обязан выбрать самый безопасный вариант: минимальное изменение, без прямого изменения типовой конфигурации, ролей, RLS, проведения и движений.

## Правила размещения новых объектов

- Новые объекты метаданных добавлять в: основную конфигурацию / расширение / уточнять по задаче.
- Префикс новых объектов: `<заполнить или оставить пустым>`.
- Новые общие модули размещать в подсистеме: `<заполнить>`.
- Новые роли создавать отдельно, не изменяя типовые роли без явной команды.
- Новые команды и формы размещать рядом с существующими аналогами, если проектный стандарт не говорит иначе.
